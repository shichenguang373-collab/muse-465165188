# 微信桥排障手册（老板 2026-10-15 整理）

| 查到什么 | 原因 | 处理 |
|---|---|---|
| state/ 下有 NEEDS_RELOGIN 文件 | 登录凭据失效 | 重新 login 扫码 |
| serve 进程不在了（state/serve.pid 对应的进程不存在） | 进程又挂了 | 重新拉起，并检查 watchdog.sh |
| 日志反复出现 Tunnel connection failed: 403 | 出口代理又拦了 | 让代理放行 ilinkai.weixin.qq.com，或换网络 |
| 日志有"已发送回复"，但微信没显示 | 回复被微信丢弃，常见是回复用的凭证过期，或被限流 | 你在微信里先发一条新消息，刷新凭证 |
| 进程在、没有报错、也没有任何新日志 | 长轮询卡住 | 重启 serve |

## 实战补充（2026-10-15）

1. **重复消息不要直接当网络抖动跳过**。worker 曾把 10:37 的重复提问误判为网络重发、
   直接标 processed 不回复——而用户其实是没看到 10:30 的回复才又问的。
   查送达时必须按**本条消息的 id**去 serve.log 里找对应的「已发送回复」，
   不要拿上一条消息的发送记录当证据（当时就查错了 ID）。
2. **补发流程**：processed.json 里已有 ID 时 worker_send.py 会直接跳过。
   要补发，先把该 ID 从 processed.json 移除，再调 worker_send.py，
   它会重新入队并标 processed。用 inbox 里**最新一条**的 context_token 发
   （用户发新消息会刷新凭证，旧 token 可能已过期——这正是上表第 4 行的解法）。
3. **403 连刷**：2026-10-15 早 09:54 前曾连续 38 次
   `Tunnel connection failed: 403 Forbidden`，重启 serve 后恢复，
   当天之后未再出现。属出口代理拦截，非登录问题（无需重新扫码）。
   （后续发现：出口代理凭证约 2 小时轮换一次，09:34/11:28 两次过期导致 403；
   看门狗已加连通性检查，断线 5 分钟内自动重启 serve 自愈。）

## 血泪教训（2026-10-15 11:35）

4. **重新扫码 ≠ 刷新旧机器人，而是建一个全新机器人。**
   旧 bot（1e3b54959beb@im.bot）扫码后得到的是新 bot（0af17d4d003a@im.bot），
   旧 token 会被顶掉（-14 失效），旧 serve 必须停掉、换新会话重启。
   用户微信里会出现两个机器人聊天窗口，务必让用户确认在和新机器人聊，
   并给新机器人改备注名区分。不要在没确认的情况下连续扫码，会越建越多。
